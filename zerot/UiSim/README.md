# UiSim - check the plugin windows without VaM or Unity

Runs the real plugin DLLs against a small re-implementation of the UnityEngine APIs they use
(IMGUI auto-layout engine, uGUI RectTransform layout, config, coroutines), renders each window to a PNG and
flags text that is cut off or spills out of its box. No VaM, no Unity license.

    cd zerot\UiSim
    copy built plugin DLLs into .\in   (host DLLs) and .\in\cores   (their core DLLs, e.g. PenetrationCounter.dll)
    powershell -File regen.ps1         # only when a plugin references new VaM/Unity API: regenerates VamStubs.g.cs
    powershell -File check.ps1         # every plugin x default / collapsed / minsize / scale2 / scalesmall
    powershell -File check.ps1 -Only CounterThrust
    bin\uisim.exe in\X.dll --out out --set Window.Collapsed=true --w 1280 --h 720   # one render, PNG in .\out

Pieces
- UnityShim  hand-written UnityEngine/BepInEx subset (Core, Imgui, Layout = port of Unity's GUILayout algorithm, Gui = draw+clip checks, Ugui)
             + VamStubs.g.cs generated by StubGen (signatures copied from the real VaM_Data\Managed assemblies)
- Runner     retargets the plugin's assembly references to UnityShim with Cecil, runs Awake/Start/Update/OnGUI, renders
- StubGen    emits stubs for every VaM/Unity type or member a plugin references that the shim lacks (reports missing members of hand-written types)

Caveats
- Text metrics use Arial at 13 px (my recollection of the legacy IMGUI default; change TextMetrics.DefaultPx if real VaM differs).
- Plugins run with no atoms/scene, so only empty-state UI is checked; native VaM UI hosted inside SmartWardrobe/Detached is not simulated.
- ZeroT.ParticlePinnacleUiSkin (Harmony) is not simulated; its layout is RlChrome.TitleRow, which the other plugins exercise.
